# v2.4.0：主动关键信息与科研记忆演化

- 日期：2026-08-05
- 状态：待合并
- 版本：2.4.0

## 背景与根因

原有 v2.3 具备“项目内捕获、用户批准后晋升”的两级经验闭环，但仍缺少三个可执行环节：总控何时主动询问关键信息、项目收尾时如何主动呈现候选、不同重要性的经验应记录到什么精度。若只追求短摘要，会损失重要工作流的原因与例外；若完整保存所有过程，又会增加 Token、噪声和错误记忆风险。

## 核心决策

1. 采用“先查后问”：先检查上下文和项目材料，再调研权威公开事实，只问用户独有且会改变路线的决定。
2. 采用 A/B/C/D 分级：重要协作原则和稳定工作流详细记录，低影响经验只保留关键步骤，项目特例不晋升。
3. 项目收尾由 Sol 先生成 3–5 条高价值候选摘要，再询问批准全部、指定子集、拒绝或延后。
4. 重复出现只提高候选优先级，不使用机械次数阈值替代授权。
5. 当前明确指令优先于长期记忆；未回复不写入，同一候选集无实质变化时不重复询问。

## 主要变更

- 新增共享协议 `shared/PROACTIVE_INQUIRY_AND_MEMORY_PROTOCOL.md`，作为唯一行为契约。
- 更新总控、需求澄清、仓库规则、项目规则、启动提示和 SOP。
- 为项目状态和复盘新增候选集 ID、摘要指纹、授权状态与防重复字段。
- 为个人工作台和全局经验库新增分级模板、冲突/替代关系以及查看、修改、废弃或删除控制。
- 行为评测从 18 个增至 24 个；确定性测试增加跨文件协议标记与工作区集成断言。

## 兼容与数据保护

- 不新增 Agent、Skill、常驻 Runtime 或自动记忆服务。
- 现有项目与旧记忆条目继续有效；新字段为增量模板，不删除历史。
- 项目敏感信息、原始数据、失败记录和版本历史仍留在项目内，不因用户删除个人记忆而被误删。
- 公共 Skill 缺陷只进入 `SKILL_FEEDBACK.md`，仍需用户确认、独立评审和回归测试。
