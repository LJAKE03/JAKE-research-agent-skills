# 科研上下文效率协议

本协议用于需要多来源、多文件、长日志、跨阶段交接或正式科研写作的任务。简单问答和已知单点读取不加载本协议。目标是减少无关上下文和重复交付，同时保留科研证据的可追溯性；它不是新的 Skill、Agent、压缩运行时或外部依赖。

## 1. 基本原则

- 先减少不必要的获取，再压缩确有必要的内容。
- 先复用已经确认且仍然新鲜的结论和定位，再补读当前缺口。
- 摘要必须可恢复到原始来源；省略不等于删除证据。
- Token、调用次数和速度不能凌驾于科研准确性、可复现性和安全边界。
- 不把第三方项目自报的节省数字当作本套件性能证据。

## 2. 上下文获取阶梯

按最低充分层级获取信息，证据不足才进入下一层：

1. **已有状态与定位**：复用当前任务卡、已验收 handoff、PROJECT_STATE、证据编号和已知符号。
2. **元数据与提纲**：查看文件清单、标题、目录、Schema、函数签名、代码提纲或数据字段。
3. **精确片段或符号**：只读取当前断言需要的段落、表格、函数、配置段或日志窗口。
4. **必要关系邻域**：补充直接调用者/被调用者、相邻证据、上下游变换或对照工况。
5. **有理由的全文**：只有片段会破坏语义、来源需要整体核验或前述层级无法验证时才读取全文，并记录理由。

达到验收条件后立即停止。同一范围最多允许一次有理由的收窄或扩展；仍不足时返回缺口，不进行无界扫描。

## 3. 结构预算与停止条件

预算使用可观察边界，不伪造无法测量的精确 Token 数：

- 限定候选目录、文件类型、时间范围、来源层级、字段或符号；
- 限定首次返回的证据、文件、符号或日志窗口数量；
- 将发现、验证、写作分别记账，不能用一种预算挤占另一种；
- 大结果写入文件，对话和 handoff 只保留摘要、定位、限制和下一动作；
- 连续两次同类失败后改变方法，禁止用相同命令无限重试。

停止条件至少包括：当前问题已回答、验收断言已满足、边界外信息开始占主导、来源冲突需要 Sol 裁决，或继续读取的成本超过预期信息增益。

## 4. 上下文账本

任务内维护一个轻量账本，不要求修改 STAGE_HANDOFF.schema.json。按定位和新鲜度将内容标记为：

- new / reused / changed / omitted
- new：本轮首次获取并交付；
- reused：此前已经验收，来源未变化，本轮只引用定位或结论编号；
- changed：来源、配置、代码、数据或任务前提已变化，必须重新验证受影响部分；
- omitted：与当前目标无关或已由可靠摘要覆盖，保留恢复定位与省略理由。

只有出现来源变化、任务问题变化、现有摘要不足或质量门要求精确复核时，才重新交付 reused 内容。无法确认新鲜度时标记 unknown，不得假装未变化。

## 5. 可逆省略

压缩长日志、JSON、代码、论文摘录或工具输出时，交接至少保留：

- 原始文件、URL、DOI、页码、表格、行号、符号或记录键；
- 摘要覆盖范围与未覆盖范围；
- 省略理由；
- 触发恢复原文的条件；
- 需要定点验证的断言。

原始材料仍留在其原位置。Worker 不把“未显示”写成“不存在”，也不把静态索引、摘要或推断提升为最终科学证据。

## 6. 科研无损区

以下内容不能只凭有损摘要进入论文、报告、参数决策或最终结论，必须保留精确值、条件和来源定位：

- 公式、变量定义、单位和换算关系；
- 数值、有效位数、误差、不确定度、统计口径和样本量；
- 实验/仿真工况、边界条件、初始条件、材料与软件版本；
- 关键方法参数、过滤与数据变换；
- 否定结果、异常、失败案例和反例；
- 直接支撑最终结论的原始引文、表格、图和代码实现；
- 安全、成本或不可逆操作所依据的事实。

其他内容可以摘要，但必须遵守可逆省略。质量门发现无损区缺少精确定位时返回 REVISE 或 BLOCKED。

## 7. 最小实现阶梯

科研代码、脚本、模板或工作流需要修改时，依次判断：

1. 需求是否真的需要新增实现；
2. 当前项目是否已有可复用能力；
3. 标准库、软件原生能力或平台功能是否足够；
4. 已安装且已批准的依赖是否可以复用；
5. 只有前四项不满足时，编写满足验收条件的最小新实现。

最小实现不等于代码高尔夫。不得删减输入验证、异常处理、单位检查、数据保护、安全边界、可访问性或科研复现信息。

## 8. 交接中的 Context Receipt

需要跨 Agent 或阶段交接时，可在现有 deliverable 文本内附加紧凑收据，不新增顶层 Schema 字段：

```markdown
## Context Receipt
- freshness:
- ledger: new / reused / changed / omitted
- acquired:
- reused:
- omitted_and_reason:
- recovery_locators:
- lossless_verification:
- remaining_gap:
```

只在上下文规模、重复交付或有损风险值得记录时使用；简单任务不制造收据。

## 9. 评价纪律

评价改动时同时比较科研质量、输入/输出 Token、工具调用次数、重复读取次数、完成时间和失败率。未完成同任务、同输入、同验收标准的旧版/新版对照前，不得声称固定节省比例。若效率提升伴随证据丢失、数值错误或更多返工，判定为无效优化。
