# 新科研项目 SOP

## 1. 项目创建

1. 每个项目必须使用独立目录，统一命名为 `project-编号-项目名`，例如 `project-0001-氨燃料供给系统`。
2. 使用科研项目创建脚本生成目录，不手工复制模板，不覆盖已有项目。
3. `PROJECT_INDEX.json` 是项目编号和状态的唯一索引；项目正文、数据和结果全部留在对应项目目录。
4. 索引状态为 `initializing` 表示项目初始化尚未完成；恢复或核对该项目后才能开始任务，不得静默删除或跳过该记录。

## 2. 项目启动

1. 读取项目 `AGENTS.md`。
2. 需要恢复、跨阶段追踪或高影响决策时读取 `PROJECT_STATE.md` 和 `PROJECT_OVERRIDES.md`。
3. 读取个人工作台中的稳定偏好。
4. 只按当前任务的阶段、工具和标签检索相关全局经验，不全文加载全部历史。
5. 按 `PROACTIVE_INQUIRY_AND_MEMORY_PROTOCOL.md`（由总控从已安装的 `shared` 目录加载）以“检查项目材料—调研权威公开事实—询问用户独有决定”的顺序获取高影响信息；低影响可逆事项声明假设后继续。
6. 当前明确指令优先于当前项目边界和长期记忆；仅当冲突会实质改变结果时提出一个聚焦确认。

## 3. 项目执行

1. 项目特例写入 `PROJECT_OVERRIDES.md`。
2. Skill 使用问题写入 `SKILL_FEEDBACK.md`。
3. 失败、异常、关键参数、有效方法及其证据在阶段边界或项目收尾时写入项目复盘；不要为每个小动作追加流水账。

## 4. 项目收尾

1. 完成最低充分质量门，核对交付物、未解决项和敏感信息。
2. 完成 `08_质量门与复盘/PROJECT_RETROSPECTIVE.md`。
3. 将经验按 A/B/C/D 重要性和项目特例、工作偏好、通用经验或 Skill 缺陷分类；重要习惯详细、次要经验简要。
4. Sol 先主动生成带编号的候选摘要，再询问用户批准全部、指定子集、拒绝或延后；没有候选时明确记录“无”。
5. 只有用户明确批准的条目才写入 `RESEARCH_WORKBENCH.md` 或 `GLOBAL_LESSONS.md`；未回复不得写入，同一候选集无实质变化时不重复询问。
6. 更新 `PROJECT_STATE.md` 与 `PROJECT_INDEX.json` 的交付状态和记忆检查点状态。
