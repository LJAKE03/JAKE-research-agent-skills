# 上下文效率协议提案

## 问题

现有套件已经通过紧凑任务卡、证据定位、代码上下文胶囊和限定检索降低上下文开销，但尚未形成跨检索、代码、写作与质量门共享的获取阶梯、重复交付控制、可逆省略规则和科研无损边界。

## 依据

- 现有总控要求只传递当前任务所需的最小上下文，但没有定义何时从定位扩展到片段、相邻关系或全文。
- `07-code-context` 已限制重复扫描，但没有记录同一任务中已经交付的定位与内容状态。
- 写作与质量门要求复用证据包，但没有统一说明哪些科研内容不能被摘要替代。
- 外部项目的可迁移思想包括：符号优先检索、交付去重、可恢复压缩、缓存友好的稳定上下文和最小实现阶梯；不引入其代理、运行时、二进制或性能宣传数字。

## 范围

新增一个共享 `CONTEXT_EFFICIENCY_PROTOCOL.md`，由总控按需加载，并在外部检索、学术写作、质量门和代码上下文 Skill 中以短引用接入。保留单一总控，不新增顶层 Skill，不修改 `STAGE_HANDOFF.schema.json`。

## 拟议变更

1. 定义“已有定位 → 元数据/提纲 → 精确片段/符号 → 必要关系邻域 → 有理由的全文”的上下文获取阶梯。
2. 定义任务内上下文账本，区分 `new`、`reused`、`changed`、`omitted`，避免无变化内容重复交付。
3. 定义可逆省略：摘要必须保留源定位、恢复条件和未覆盖范围。
4. 定义科研无损区：公式、单位、数值、工况、参数、否定结果、异常和支撑最终结论的关键实现必须精确验证。
5. 定义代码最小实现阶梯，优先不新增、复用项目能力、标准库/平台能力和既有依赖。
6. 使用结构预算与停止条件，不伪造精确 Token 节省比例。

## 回归测试

- 共享协议存在且被总控及四个相关功能 Skill 引用。
- 协议包含获取阶梯、上下文账本、可逆省略、科研无损区、最小实现阶梯、停止条件和禁止固定节省声明。
- 代码上下文评测覆盖符号优先、重复读取防护和关键数值/单位无损验证。
- 现有路由、模型、Windows、编码、启动器和安装测试继续通过。

## 版本影响

这是可复用的新能力，建议将套件版本从 `2.1.0` 升级为 `2.2.0`，并在 Changelog 的 Unreleased 部分记录。

## 回滚

删除共享协议及各 Skill 的短引用，恢复新增评测与测试断言，并将版本文件恢复为 `2.1.0`。不涉及用户级配置、外部依赖或数据迁移。
